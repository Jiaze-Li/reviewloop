# ReviewLoop decisions

Current LOCAL-only decisions. Previous PR-mode decisions are available in Git
history; GitHub PR review belongs to claude-review-bot.

| # | decision |
|---|---|
| D1 | Worker-owned execution. The coding agent the user is talking to implements, tests, and pushes. |
| D2 | ReviewLoop is not a coding agent. It never writes application code. |
| D3 | Planner removed. The Worker receives the user's prompt directly; there is no task decomposition, no Fast/Full path, no task queue. |
| D4 | Executor pool removed. No internal Executor role, no Sonnet-only chain, no fresh rework sessions. |
| D5 | The Worker uses its host's normal permissions. ReviewLoop does not sandbox the Worker (allowed_files / exact verification commands / no-pipe restrictions are gone). |
| D6 | Git evidence is authoritative. The baseline-to-current diff is the primary Reviewer input. |
| D7 | The Gate is verification, not a command-permission system. 0 model tokens. |
| D8 | P1/P2 block completion; P3 does not. Root `CLAUDE.md` review conventions are aligned to this. **Superseded for code loops by D43.** |
| D9 | The first actionable REWORK goes directly to the same Worker — no Supervisor, no new session. |
| D10 | Supervisor is exception-only: at most one successful escalation per current review gate, only after a genuine changed implementation left the same blocking finding. PHASE_PASS resets this gate-local flag; task-wide model-spend safety does not reset. |
| D11 | Local waiting never wakes the Worker or a model. `WAITING_FOR_REVIEW` is a durable state. |
| D13 | Same evidence in the same review scope cannot spend twice. `NO NEW INFORMATION → NO NEW MODEL CALL`, enforced at the authority boundary. A phase/final scope change is new review information and is fingerprinted into the review-state evidence. |
| D14 | ReviewLoop never auto-merges and never force-pushes. |
| D15 | The Worker-facing MCP surface is exactly two tools; COMMON ≤ 3.4 KB (raised from 2.5 KB by D39, to 3.3 KB by D41, to 3.4 KB by D42); result payloads are compact and never carry raw evidence blobs. |
| D16 | `~/.reviewloop` is the runtime root. `~/.supergpt` is never read, written, or auto-resumed; a legacy V2 snapshot fails closed. |
| D17 | Reviewer/Supervisor transports are narrow single-turn inference from one isolated empty scratch cwd — never a second coding Worker. One physical attempt per call; failover is the controller's, not the transport's. |
| D18 | Stable model-family identity is preserved without concrete version pins: `agy:*` resolves from the runtime catalog, `codex:default` delegates to the Codex default, and `claude:opus` passes the stable provider alias `opus`; telemetry records the concrete model actually used. |
| D19 | A pool family is either a wired, selectable transport or explicitly UNAVAILABLE with a reason. No phantom fallbacks. `codex`/`claude` wire only after zero-token `--version` plus local auth-status preflights succeed. |
| D20 | Authentication has two boundaries: local `codex login status` / `claude auth status` failures are pre-dispatch and make that family unavailable; an auth-looking error after a prompt-bearing invocation starts is `PROVIDER_AUTH_REJECTED`, has unknown spend unless provider usage proves otherwise, and must not authorize failover. |
| D21 | `benchmark:transports` is zero-provider and covers both transport narrowness and controller E2E-A (one-round PASS), E2E-B (REWORK→PASS), and E2E-C (persistent blocker→Supervisor once). |
| D22 | Every AGY family runs through the `reviewloop-minimal` custom agent (`inheritCustomizations: false`), provisioned deterministically/idempotently at `<isolated gemini dir>/config/agents/reviewloop-minimal/agent.md` and reached with `--gemini_dir` — **not** a workspace `.agents/` path (agy does not reliably discover a workspace-local custom agent and silently falls back to the default agent when `--agent` is unresolvable). Never provisioned into the user's HOME or AGY global config. Effective loading is checked by a zero-model startup capability probe **and** per-call verification; any failure fails closed (AGY families UNAVAILABLE) — ReviewLoop never accepts an AGY default-agent reply. Definitive isolated-agent live result: `agy:gemini-supervisor` medium Supervisor `usageVolume 2933`, `effectiveLoadingVerified`. Earlier ~40k (isolation not in effect — default agent) and ~6.7k (pre-verification) figures are **not** a baseline. No production family is `highContext`; both Gemini role heads are in ordinary automatic routing. |
| D23 | `usageVolume` (the `MAX_USAGE_VOLUME` safety ceiling) is provider/family-aware (`usageAccountingOf`), keyed off the family/provider in the CallIntent, never a model name. Precedence: authoritative provider-reported total (trusted **only** from a token-total field confirmed for that class — `AUTHORITATIVE_TOTAL_ALIASES`; a bare `total` and any total on an unknown provider are ignored) → family fallback (`openai` = input+output, cache-read is a subset; `anthropic` = input+output+cache_creation+cache_read, separate categories) → conservative additive flagged `semanticsKnown:false` for AGY-without-total / unknown providers. A fallback reports known only when its mechanically-required fields are present; a partial post-dispatch usage object (`volumeResolved:false`) fails closed into the existing `MODEL_SPEND_USAGE_UNRESOLVED` / `ReservationLedger` UNRESOLVED path, never read as 0. Cached tokens are never double-counted; raw breakdown + `usageAccounting` provenance persisted per record. UNKNOWN != ZERO preserved. |
| D24 | Gemini production routing uses two role-specific stable family identities, each with a FIXED reasoning effort: `agy:gemini-reviewer` (`defaultEffort: low`, reviewer role only) is the Reviewer head; `agy:gemini-supervisor` (`defaultEffort: medium`, supervisor role only) is the Supervisor head. Editing `DEFAULT_ROLE_POLICY`'s `effort` field alone is insufficient — the concrete `agy` model is resolved and bound at provider-pool construction from the family's own `defaultEffort`, so a single `agy:gemini` family can only ever carry one effort. Both new families resolve from `catalogPrefix: gemini-`, share the one `agy-gemini` quota pool (`DEFAULT_QUOTA_TOPOLOGY`) so a Gemini quota/rate cooldown on either takes both out of routing, and reuse the existing `reviewloop-minimal` isolation / AGY transport / token accounting / fail-closed behaviour. Reviewer routing: `agy:gemini-reviewer → codex:default → agy:sonnet → agy:gpt-oss → claude:opus`. Supervisor routing: `agy:gemini-supervisor → codex:default → agy:sonnet → claude:opus`. Telemetry stays honest: the concrete `-low` / `-medium` id resolved for the family is exactly what the transport passes as `--model` and what the durable spend record persists. |
| D25 | Brand-new Worker file attribution is structural, not content-based: any file untracked at baseline makes every brand-new Worker file (tracked add or untracked) fail the evidence closed — ReviewLoop keeps only a digest per baseline-untracked file and will not chase lossless transforms (base64/gzip/hex/NUL-stripping). A clean starting tree is unaffected. Independently: a git submodule (gitlink) in the Worker's tracked diff — new commits or a dirty submodule worktree — fails closed (ReviewLoop does not recurse into submodules); and a single untracked file is read into memory only up to an 8 MiB cap, larger files are digested with a bounded streaming read and, if brand-new Worker output, fail closed rather than OOMing the MCP process. |
| D26 | Cross-host lease loss is fail-closed. `renew()` is a compare-and-swap on the inode (write only through the descriptor opened on the published lock file), so it can never overwrite a successor lease. A displaced owner that resumes mid-review must not start a new paid model dispatch or write ReviewLoop durable state: `assertLeaseHeld` (a fresh ownership probe that latches on any non-confirmation) gates both boundaries, and a lost lease aborts the call to a read-only `WAITING_FOR_REVIEW` — the new owner reconciles state. |
| D27 | The Reviewer and Supervisor first-choice candidates are pinned to DIFFERENT quota pools so a cooldown on one role's primary never disables the other's. Reviewer first choice is `agy:opus` (AGY-hosted Claude Opus, `agy-claude-gpt` pool); Supervisor first choice stays `agy:gemini-supervisor` (`agy-gemini` pool, unchanged). `agy:opus` is `PRODUCTION_ROLE_CAPABILITIES: ['reviewer']` only — the Supervisor pool is untouched. It resolves its concrete Opus dynamically from the AGY runtime catalog (`catalogPrefix: 'claude-opus-'`, `defaultEffort: null`) at pool construction — never a long-term version pin — and shares the `agy-claude-gpt` quota pool with `agy:sonnet` + `agy:gpt-oss`, so one `PROVIDER_QUOTA_EXHAUSTED` / `PROVIDER_RATE_LIMITED` cooldown on that pool skips all three at route time with no wasted probe. `agy:opus` reuses the existing `reviewloop-minimal` isolation, AGY transport, token accounting (`accountingClassOf` → `agy`), ModelSpendAuthority, token sentinel and bounded failover unchanged. Reviewer routing: `agy:opus → agy:gemini-reviewer → codex:default → agy:sonnet → agy:gpt-oss → claude:opus`. Supervisor routing unchanged: `agy:gemini-supervisor → codex:default → agy:sonnet → claude:opus`. |
| D30 | Final routing-hardening invariants (`a1cfe2c` → `928f79f`). `agy:opus` eligible → must be the Reviewer primary selection, enforced by `assertRoutePrimaryFirstInvariant` (throws `ROUTE_PRIMARY_NOT_EVALUATED` / `ROUTE_PRIMARY_REASON_NOT_ENUMERATED` / `ROUTE_PRIMARY_SKIP_UNPERSISTED` on violation). Any pre-dispatch skip must record a durable, enumerated `ROUTE_SKIP_REASONS` value before route advances; an unpersisted or unenumerated decision fails closed rather than passing through. A candidate with `transportAvailable === false` is skipped `NO_TRANSPORT` and can never be selected regardless of health/quota. Stale provider health is cleared only by a zero-token revalidation probe scoped to the exact failure class that can prove recovery — only `reasonCode: AGY_PROVISIONING_FAILED` is eligible for re-probe; every other reasonCode requires an MCP server restart, never a same-process re-probe. `RouteAuditLog` durably records `loopId` / `round` / `operationId` / `attempt` / `chunkIndex` / `chunkTotal` per routing decision — no failover or chunked round collapses into one abstract audit entry. |
| D31 | Large tasks may carry a frozen ordered phase plan inside one ReviewLoop objective. A phase uses the same zero-token Gate → Reviewer → Worker REWORK → exception-only Supervisor engine and returns non-terminal `PHASE_PASS`; only the final whole-task gate may return terminal `PASS`. Phase order/objectives/exit criteria/carry-forward invariants are objective-fingerprinted. Convergence state (gate round, finding history, Supervisor-once flag, Gate-repair count) is gate-local and resets on PHASE_PASS, while the original baseline, global audit round, durable token/cost spend, Token Sentinel, provider accounting, reservation/information ledgers and loopId remain task-wide. No nested `reviewloop_begin` is permitted between phases. |
| D32 | Reviewer quota exhaustion. An AGY quota/credit rejection is settled zero-consumption (`SETTLED_KNOWN`, `PROVEN_QUOTA_REJECTED_ZERO`) and auto-fails over ONLY when ALL hold: `AGY_NONZERO_EXIT`, empty stdout, usage evidence explicitly absent, and canonical quota/credit wording (`agyQuotaClassifier.js`). Non-zero exit, short duration, a bare `RESOURCE_EXHAUSTED`, plain rate limits, mid-stream wording or any usage evidence stay UNKNOWN → `UNRESOLVED` (fail closed). Generic CLI `PROVIDER_QUOTA_EXHAUSTED` carries no such proof and is not zero. A proven rejection cools the whole shared quota pool; the production pool registry is disk-backed (`~/.reviewloop/quota-pools.json`, re-read on change) so cooldowns survive MCP restarts. An `UNRESOLVED` reservation now persists bounded content-free `failureDiagnostics` (stderr excerpt, envelope, stdout-empty, usage-evidence state). Human recovery (`acknowledge-spend --exclude-family/--exclude-pool`) records loop-wide routing exclusions on the acknowledgement (append-only, amendable on an already-acknowledged reservation); routing skips them and `authorize()` rejects them (`FAMILY_EXCLUDED_BY_HUMAN`) as a backstop. History is never rewritten and each acknowledgement still grants exactly one retry. |
| D33 | LOCAL phase gates are phase-scoped. `PHASE_PASS` records a hash-chained snapshot (`phaseBaseline` = head + baselineRef, covered by the completion proof) of the just-certified tree; the next phase gate diffs from it instead of from the `reviewloop_begin` baseline, which stays the immutable objective baseline. Fallbacks to the cumulative diff, never worse than before: the final gate, PR mode, a boundary with untracked files (D25 would make new Worker files unattributable) or incomplete attribution, and a phase whose own delta is empty or unattributable. The Reviewer prompt states the diff scope. Same-family transient retry (auth-refresh race, pre-send network loss) is provider-neutral: any transport that sets `transientAuth` / `transientNetwork` participates; only AGY has classifiers today. |
| D34 | An oversized final gate no longer stops a phased LOCAL loop when it can be reduced without losing coverage (`finalDiffReducer.js`). Each `PHASE_PASS` records the files its gate reviewed (hash-chained) and a boundary snapshot, also after the last phase. The final gate reviews files changed in 2+ phases, files changed since the last boundary, and files no phase recorded; a file changed in exactly one phase and untouched since was fully covered at that gate and is omitted with an explicit NOTE, but the Reviewer is never handed an empty diff: remaining files are added newest-phase-first up to one chunk (within the whole chunk budget), and with nothing to show the reduction fails closed. Interactions between omitted single-phase files are not reviewed jointly; the deterministic Gate's global checks cover them. All-or-nothing: unless the diff splits into exactly one attributable unit per changed file, the old behaviour (REVIEW_TOO_LARGE) stands. |
| D35 | `reviewloop reopen-gate` is the human override for a spent convergence budget (like `acknowledge-spend` it is CLI-only, lease-guarded and never reachable from the Worker MCP surface). It reopens only the current gate: fresh epochs/rounds/Supervisor escalations; objective, baseline, completed-phase proof chain, spend and call ceilings, Token Sentinel and information ledger are untouched. Refused when the Sentinel tripped or after 3 reopens. `reviewloop_begin` returns advisory `planWarnings` (never blocking) for phases with no mechanical verification and, in LOCAL mode, for untracked files / incomplete attribution at begin (D25 would otherwise only surface at the first review, after work was done). |
| D36 | Two further guards against stranded long tasks. (1) A gate whose deterministic Gate FAILs (or whose verification plan drifts ) more than `MAX_GATE_REPAIRS` times (**env knob and numeric default superseded by D45**; now configured in `reviewloop.settings.json`, counted per gate, reset by PHASE_PASS and by `reopen-gate`) stops with `HUMAN_REQUIRED` + `budgetExhausted`; before this `gateRepairCount` was only a counter, so a Gate failing for a different reason each time could loop without bound. Identical states are still caught earlier by `NO_PROGRESS`. (2) `reviewloop resume` (CLI-only, read-only) prints a prompt for a FRESH Worker session built from durable loop state; ReviewLoop still never spawns or restarts a Worker (D1), a spent budget is redirected to `reopen-gate` (such loops are listed by default discovery). The frozen contract is printed in full: a fresh Worker has no other way to retrieve it. |

| D37 | **LOCAL-only ownership.** ReviewLoop captures local baselines, Gate proof, independent Reviewer/Supervisor decisions and durable spend. GitHub PR discovery, validation, verification, final audit and review-session publication are exclusively handled by claude-review-bot. Retired PR loops stay on disk but cannot resume or become LOCAL. | 
| D38 | **Design review is LOCAL-only.** The `design` taskType (`reviewloop_begin({ taskType: 'design' })`, #37) is the only design-review path. A GitHub-bot design path (claude-review-bot Design commands, workflow, session comment and decision function; CRB-DESIGN-01, claude-review-bot PRs #70/#72) was designed through contract v0.11 and then dropped by the product owner on 2026-11-13 before any implementation; both PRs were closed unmerged. Do not re-design or re-propose GitHub-side design review. Extends D37. |
| D39 | **Unified Design review (ENG-RL-UNIFY-20261114).** Design runs on the SAME engine as Code (Gate, Reviewer pool, shared epoch/Supervisor escalation policy, spend ledger, checkpoints, resume). A new Design loop is created with a frozen `reviewTarget` (one repository-relative design file that must NOT exist at begin; `contractText` = the complete Plan; `phases=[]`) and routes ordinary review through the Reviewer pool. `reviewTarget` is the version marker: a Design loop WITHOUT it is the legacy path and keeps its Supervisor-pool route, so resuming it after an upgrade never changes route or cost (`usesSupervisorPoolForReview`). The field is folded into the objective fingerprint only when present, so older objectives keep their hash. Each round, before any model spend, the whole current file is read safely (relative path, no symlink on the way, regular file, strict UTF-8, ≤64 KiB, never truncated) and must sit inside ONE Reviewer chunk; otherwise REWORK with a reason and zero Reviewer calls. After the Reviewer returns, the file and the Worker delta are re-read and compared; any difference means no PASS (the pre-Reviewer Gate stabilization loop does not cover this). PASS persists and returns `designSha256` (SHA-256 of the whitespace-trimmed UTF-8 content, the same normalization `contractText` receives). Code `reviewloop_begin` accepts an optional `designSha256` and refuses a non-matching `contractText`. `designSha256` is a content-consistency check, NOT proof of Design PASS or of user authorization; no GitHub reads, credentials or authorization parsing were added. Known limit: on runtimes without an atomic whole-path symlink guard (not Darwin) gitEvidence cannot attribute a new untracked file under a parent directory, so use a repository-root target there; `reviewloop_begin` warns. The COMMON budget moved from 2.5 KB to 3.2 KB for the Design flow and the optional personal-skills method entry. The Design-pass PR comment no longer carries the `<!-- reviewloop-design:v1 -->` marker or `Status: DESIGN_PASS` (nothing in ReviewLoop or claude-review-bot parsed them; leftovers of the dropped bot path in D38): five plain lines plus `designSha256`. Extends D38. |
| D40 | **A loop says which repository it is bound to** (issue #40, point 2). `reviewloop_begin` returns `repositoryRoot` (the bound `cwd`) and `branch` (display only, never part of any identity or fingerprint; `null` when unreadable, `(detached HEAD)` when detached). The `NO_PROGRESS` returned when no Worker change exists since begin names the bound root and current branch and says edits in any other repository or git worktree are not seen. Only that reason changed; identical-state `NO_PROGRESS` results are unchanged. Not done: detecting that ANOTHER worktree has changes (needs guessing which directories to scan). |

| D42 | **Design review is two-stage** (reviewMode `design-two-stage`). For a Design loop with `reviewTarget`, the Reviewer first proposes up to two approaches from the Plan and controller-read tracked files WITHOUT ever seeing the design file; the Supervisor then compares them with the Worker's design, runs the original design blocker checks and writes the user-facing `designPassComment` (the controller rewrites its `designSha256:` line). Material difference triggers at most 2 idea exchanges, then `HUMAN_REQUIRED`; `NEEDS_HUMAN` can stop in any round; a Plan-level doubt is surfaced as `planConcern` and never blocks. Chosen over a Reviewer file tool (cannot enforce a per-path block, per-CLI injection) and over routing file reads through the Worker (state-machine and tamper cost). `code` and legacy Design (no `reviewTarget`) are untouched and re-derive their mode from fingerprinted fields. At most 2 Reviewer + 1 Supervisor call per round; design round cap is `maxReviewRounds + 2`. Every begin/review result carries a fixed `statusLine`. Contract version 13 → 14; COMMON budget 3300 → 3400 bytes (user-approved). Supersedes the "<=5 plain lines" design-pass comment rule from D41. |
| D43 | **Code loops block on P3 too.** claude-review-bot made an open P3 block READY (claude-review-bot #83), so a loop that PASSed with P3 left open was guaranteed to come back as PR findings. New code loops default `blockingSeverities` to P1+P2+P3; design loops keep P1+P2 (the design Reviewer is told to file speculative concerns as P3). The normalizer now keeps P3 as its own severity instead of folding it into OTHER, which also makes an explicit `blockingSeverities` containing P3 actually work (before, it could never match). The Reviewer prompt is generated from the objective's own `blockingSeverities`; when P3 blocks it defines P1/P2/P3 like the bot and forbids style or speculative findings, so a nit cannot hold a gate. Persisted loops keep their frozen severities. Supersedes D8 for code loops. |
| D44 | **ReviewLoop progress is visible without the Worker's help.** Each begin/review MCP result now starts with the `statusLine` as its own text block (the JSON block follows unchanged), so the tool-call preview shows it even when the Worker does not repeat it. Progress notifications were sent with a made-up token (`loopId`) when the client had not asked for progress, and always with `progress: 1`; MCP clients drop both. They now use only the client's `progressToken`, count up, and report `gate_running`, `reviewer_running chunk i/N` and `supervisor_running`. Whether a loop ran at all is answered by `reviewloop status` on the machine that ran it, not by the Worker's word. |

| D47 | **Human-authorized Design exception after a review-TOOL stop** (RL-HUMAN-AUTHORITY-20261120, PR #67). | D48 | **Review reliability** (RL-REVIEW-RELIABILITY-20261121, PR #69; built without a Design PASS or exception — the product owner waived the Design gate). (1) *Stop causes are structured*: every `HUMAN_REQUIRED` transition carries an engine-written `cause`; old records are read only by a closed set of engine template prefixes corroborated by durable state, otherwise UNKNOWN/AMBIGUOUS with no exception eligibility; model text, labels and free-text patterns never decide a privileged category, and the human report never quotes model text (`stopCause.js`). `reviewloop restore-hold` appends a restore entry for an ambiguous old record and never edits history. (2) *Design input is budgeted before any call*: each Design stage prompt is measured whole against the strictest candidate-family limit (`min(floor(0.8 × single-call ceiling) × 3 bytes, local argv envelope)`; an unmeasured transport uses a labelled conservative default). Oversize stops with zero calls, lists component sizes and the limit's source, never trims or resends, and points at the existing human alternative-review path. It does NOT make large designs reviewable in-system (later PR). (3) *Receipts*: `⟦RL:n:hex8⟧` lines at least every 4 KiB plus one per block end must be echoed in order; a missing, extra, reordered or wrong receipt is `INPUT_INCOMPLETE` and never PASS. **What this proves and what it does not:** it detects loss that spans a receipt line; a loss lying wholly between two receipts (shorter than one interval plus one line) is NOT detected, and receipts say nothing about whether the model understood the text — they are conservative detection, not a proof of full reading, and a real-provider check of receipt echoing is NOT_VERIFIED. (4) *Retry*: only a format problem (not JSON / schema invalid) may be retried, and the retry is budget-checked again; empty, too-large and incomplete replies are never retried. (5) *HUMAN_REQUIRED is an engine-enforced hard stop*: any ordinary `reviewloop_review` call (same, changed, repeated or invalid) is refused read-only — no Gate, no model call, no write — and returns the `submissionDigest`. It is released only by `reviewloop authorize-rereview` (CLI-only, lease-guarded): one authorization covers exactly one stop and one submission digest (loop, task type, head, delta fingerprint; never the tool version), is saved as consumed before the first paid call, is restored if the call ends without spend (Gate failure, no progress, exception), allows 3 standard authorizations and requires a stated call budget beyond that, and resets no history, budget, fingerprint or ledger. Existing human actions recorded after the stop (acknowledgements, raised ceilings) still release it when no independent stop remains. The report offers a command only when its own precondition holds right now.
